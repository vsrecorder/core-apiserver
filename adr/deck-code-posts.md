# みんなの公開デッキ(deck_code_posts)

公開したデッキコードを、ログイン不要のタイムラインと個別ページで共有する機能。
2026-09-04 の企画で決めた事項と、実装上の判断をまとめる。

## 方針

- **他人の通信を媒介しない設計にする。** コメント・返信・DM・メンション・自由記述(ひとこと)は
  持たない。ほかの人の投稿にできるのは「いいね」だけ。通報も置かず、運営の非表示(`hidden_at`)だけを持つ。
  非表示・解除は `cmd/hide-deck-code-post`(`-post-id` / `-user-id`、`-unhide`、`-dry-run` 既定 true)で行い、
  psql で直接書かない。
  電気通信事業法の届出が不要な範囲に収めたい運営者の方針による(該当性の最終判断は法的確認に委ねる)。
- **投稿は既存のデッキコード(バージョン)への参照。** 投稿用の別名・本文を持たず、デッキ名・
  スプライト・コードは読み込み時に `decks` / `deck_codes` から埋める。
- **閲覧は公開。** 一覧・個別・投稿者ページ・いいねした人一覧は `OptionalAuthenticationMiddleware`。
  公開・取り下げ・いいね・取り込みの計上はログイン必須。投稿者ページ(`GET /users/{id}/deck_code_posts`)は
  公開中の投稿が1件も無いユーザには 404 を返し、投稿していない人の名前・アイコンを引けないようにする。
- **webapp 側の URL は `/shared_decks`。** `/decks` の配下に置くとログイン必須のガード・robots の除外・
  loading.tsx の継承(存在しない投稿がソフト 404 になる)で例外が増えるため、独立したルートにしている。

## テーブル

- `deck_code_posts`: 取り下げは `unpublished_at` で表し行は残す。取り下げていない投稿は1コードにつき1件
  (部分一意索引 `idx_deck_code_posts_active_deck_code_id`)。公開し直しは別の行(別ID)として作る。
  いいね数は列として持たず、`deck_code_post_likes` を数えて出す(取り消し・退会・取り下げの一括削除で
  数が狂わないようにするため)。
- **状態は2つの列で表す。** `unpublished_at`(投稿者の取り下げ・連動した取り下げ)と
  `hidden_at`(運営の非表示。`cmd/hide-deck-code-post` で入れる)。閲覧者向けの「公開中」は両方 NULL、投稿者向けの
  「公開中(枠を占有している)」は `unpublished_at` が NULL。運営が非表示にした投稿は一覧・個別・いいね・
  取り込みの対象外。投稿者本人には `hidden: true` 付きで返し(デッキの投稿一覧・個別ページ)、画面は
  「運営により非表示」と示す。取り下げはできるが、そのコードは取り下げた後も公開し直せない
  (`ErrDeckCodePostHidden` → 403。解除は `cmd/hide-deck-code-post -unhide` で、取り下げ済みも対象)。
  非表示のまま取り下げていない間は部分一意索引が二重公開を防ぐ。
- `deck_code_post_likes`: (post_id, user_id) で一意。取り消しは物理削除。
- `deck_code_post_imports`: 「デッキ登録」(取り込む)の利用記録。(post_id, user_id) で一意にし、
  同じ人が何度押しても1回として数える(押した回数を数えると水増しできるため)。取り下げても残す。
  投稿カードには「N人が登録」として出す(`import_count`)。いいね数と同じく列としては持たず、
  読み取り時に数える(退会した人の記録は物理削除されるので、その分は数から減る)。
- 論理削除は持たず、退会時は `DeckCodePost.DeleteByUserId` で物理削除する。消すのは「本人の投稿」
  「本人のデッキに紐づく投稿(他人が本人のデッキに作ったコードで公開したものを含む)」とそれらへの
  いいね、本人が押したいいね(`cmd/check-deleted-users-data` / `cmd/purge-deleted-user-data` の specs も同じ範囲)。

## ルール

- **公開し直しは同じコードにつき24時間に1回**(`DeckCodePostRepublishInterval`)。
  取り下げ→公開でタイムラインの先頭へ上げ直す操作を抑える。判定は最新の投稿(状態問わず)の
  `published_at` との差。
- **取り下げるといいねは消え、公開し直しても戻らない。** `unpublishWhere` がいいねを削除する。
- **デッキのアーカイブ・削除、バージョン削除に連動して取り下げる。** `usecase.Deck.Archive/Delete`、
  `usecase.DeckCode.Delete` が同じトランザクションで `UnpublishByDeckId/ByDeckCodeId` を呼ぶ。
  アーカイブ解除では投稿は戻さない(公開し直しは投稿者の操作に委ねる)。
- **公開できるのは本人のコードかつ本人のデッキ。** どちらかが他人のものなら NotFound
  (退会・削除の連動がデッキの持ち主単位で動くため、他人のデッキに紐づく投稿を作らせない)。
  同時に2回公開されて部分一意索引に当たったときは、先に公開された投稿を返す(冪等)。
- **デッキ・コードの公開/非公開設定(`private_flg` / `private_code_flg`)は条件にしない。**
  現状は設定を変える画面がなく作成時に必ず非公開になるため、条件にすると誰も公開できない。
  公開できないのはアーカイブ済みのデッキだけ(`apperror.ErrDeckArchived`)。
- **一覧の既定は現在の環境。** `environment_id` 未指定なら `Environment.FindByDate(今日)`(開始日が
  今日以前で最新の環境)の期間で `published_at` を絞る。過去の環境は `[from_date 0時, to_date の翌日 0時)`、
  現在の環境は開始日以降を区切らない(環境テーブルの更新が遅れて `to_date` を過ぎても、今公開される
  投稿が一覧から消えないようにする)。環境をまたぐ一覧は出さない。投稿の環境は公開した日時で決まる。
- **人気順は直近7日間のいいね数**(`DeckCodePostPopularWindow`)。同数は新しい順。
- **ACE SPEC で絞り込める。** `acespec_card_name` を渡すとその ACE SPEC を採用した投稿に絞る。
  同じカードでも収録セットごとに `card_id` が違う(「アンフェアスタンプ」は 47870 / 49349 / 45640 …)ため、
  IDではなく**カード名**で絞る(利用者にとっては1枚のカード)。候補は `GET /deck_code_posts/acespecs` が
  「環境内の公開中の投稿で使われている ACE SPEC と投稿数」をカード名で束ねて投稿数順に返す
  (判定できていない投稿は数えない)。カード画像は候補の中で1つを代表として返す。
- **スプライトで絞り込める。** `pokemon_sprite_id` を繰り返しで最大2体まで渡すと、それらをすべて持つデッキの
  投稿に絞る(位置は問わない)。webapp はデッキのスプライト選択と同じモーダル(全ポケモンから検索して2枠に
  入れる)で指定する。以前は「環境内の公開中の投稿で使われているスプライトと投稿数」を候補として返していたが、
  選び方をデッキと揃えたため廃止した。

## ACE SPEC

公開時に deckcard-api(`GET /api/v1beta/deckcards/{code}/acespec`)で判定し、
`ace_spec_card_id` / `ace_spec_card_name` / `ace_spec_image_url` に保存する。表示も保存した値から組む
(webapp が一覧でカードごとに acespec API を引かない)。接続先は `DECKCARD_API_BASE_URL`(未設定なら公開ドメイン経由)。

判定に失敗しても公開は止めず「判定なし」で保存するが、**空のまま残ると表示だけでなく OGP 画像と
ACE SPEC での絞り込みにも効き続ける**ため、取りこぼしにくくしてある:

- 問い合わせの上限は10秒(共通の httpclient と同じ)。そのデッキコードを deckcard-api が初めて見るときは
  公式サイトからの取得が挟まり数秒かかることがあり、短くすると取りこぼす(3秒にしていた間に実際に発生)。
- それでも空だった投稿は、webapp が画面に入ったときだけ acespec API から取り直して表示する
  (`DeckCodePostAceSpecRow`)。保存に失敗しただけで「ACE SPEC なし」と決めつけない。
- 保存値そのものを後から埋めるには `cmd/backfill-deck-code-post-acespec`(`-dry-run` 既定 true)。
  埋めた投稿は個別ページを1回取得して OGP 画像も作り直す(画像は内容の指紋がキーなので、
  ACE SPEC が入ると別のキーになり、取得しないと生成されないままになる)。

## 称号ティア

投稿者・いいねした人の称号ティアは `Designation.GetByUserId` で都度計算すると一覧のたびに
投稿者全員分の集計が走るため、usecase 内のプロセス内キャッシュ(10分、上限1万人)で抑える。
現在のシーズンの判定は1リクエストにつき1回だけ引く。ランク(ボール画像)と絵文字・名前は
webapp がティアから導出する。

## いいねの通知

いいねのたびに通知すると人気の投稿ほど連打になるため、`cmd/notify-deck-code-post-likes` が
毎朝(config/crontab、08:00 JST)前日分を投稿ごとに1通にまとめて投稿者へ通知する(カテゴリ `like`、
アプリ内通知 + push)。文面は「◯◯さんほかN人が「デッキ名」にいいねしました」の定型で、
投稿者自身のいいねは数えない。同じ投稿・同じ日の二重送信は `link_url`(`/shared_decks/{id}?d=YYYY-MM-DD`)を
キーに `ExistsByUserIdAndCategoryAndLinkUrl` で防ぐ。`-user-id` で投稿者を絞れる(既定は dry-run)。
